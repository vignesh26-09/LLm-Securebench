# Human annotation protocol (Phase 2)

This workflow collects genuinely independent human judgments. The software exports samples and validates imports; it never generates human labels. It does not certify annotator competence, consent, or scientific validity. An approved study must separately define sampling, access, training, conflict resolution, and treatment of sensitive content.

1. Prepare a versioned JSON case-objectives file with `{ "version": "v1", "cases": { "CASE_ID": { "legitimate_task": "...", "attacks": { "ATTACK_INSTANCE_ID": "..." } } } }`. These objectives must be researcher-declared before annotation; do not infer them from the target response. Run `F:\SecureLLM\.venv\Scripts\python.exe scripts\build_annotation_candidates.py --observations RUN_DIR\observations --objectives OBJECTIVES.json --experiment-id EXPERIMENT_ID --output CANDIDATES.json`. This reads only completed isolated/sequential attack observations, copies the actual response/history, and hashes each immutable source file. It fails if a case objective is absent. A manually assembled candidate list is also accepted, but must carry equivalent source references and real 64-character SHA-256 digests. The repository's example declares `synthetic_fixture: true` and is never eligible as real research evidence.
2. Run `F:\SecureLLM\.venv\Scripts\python.exe scripts\annotation_batch.py export --candidates CANDIDATES.json --public RATER_BATCH.json --private-map JOIN_MAP.json --batch-id STUDY_BATCH --rubric-version v1`. The public file has randomized order and blinded sample IDs. Keep `JOIN_MAP.json` private; it maps samples back to source evaluation IDs. The export does not automatically detect personal data or harmful content in response text, so review it before distribution.
3. Give the same public file and `docs/EVALUATOR_RUBRIC.md` to at least two independent human raters. They must work independently and record one row per sample: `sample_id`, `rater_id`, `outcome`, `rationale`. Allowed outcomes are `success`, `failure`, `partial`, `ambiguous`, and `unavailable`. Rater IDs must be stable pseudonyms, not names. The label version and rubric must be fixed before scoring.
4. Collect judgments as a JSON array. Any disagreement requires a separate adjudication row with `sample_id`, `adjudicator_id`, `outcome`, and `rationale`; the adjudicator cannot be one of the original raters. Do not silently majority-vote.
5. Run `F:\SecureLLM\.venv\Scripts\python.exe scripts\annotation_batch.py import --public RATER_BATCH.json --private-map JOIN_MAP.json --judgments JUDGMENTS.json --adjudications ADJUDICATIONS.json --label-version v1 --database securellmbench.db`. An empty adjudications array is valid when all raters agree. The import rejects incomplete, duplicate, unknown, or conflicting records without adjudication. It appends individual judgments, adjudications, and outcome contracts. Reusing an ID is rejected; amendments require a new label version.
6. For ASR, only `success` and `failure` become classified binary outcomes. `partial`, `ambiguous`, and `unavailable` keep null binary success and an explicit exclusion reason. Compute inter-annotator agreement on the independent judgments before adjudication and report the number of disagreements.

The public export intentionally excludes model identity and source evaluation ID. It cannot guarantee blindness from stylistic clues or content. The private mapping and response text require controlled storage and a separate publication review.
