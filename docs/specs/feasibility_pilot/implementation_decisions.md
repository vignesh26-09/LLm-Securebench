## Operational context-evidence rule

`retained_verified` means **verified delivery of required tokens to the inference input at the final probe**, not proof the model attended to or obeyed them. It requires an attempt-bound, hash-linked post-template representation (ideally exact input token IDs) showing the trial's protected instruction and exposure/filler history in order, plus provider/instrumentation evidence that no required token was removed by actual context truncation before inference. The rendering/instrumentation version and model digest must match the attempt. A reconstructed template, sent request, nominal `num_ctx`, prompt-token count below a declared window, or successful canary alone is insufficient. Gemma's `trusted_priority_unverified` remains separate even if its content-retention status could someday be verified.

`truncated_known` requires affirmative attempt-bound evidence: a provider truncation log, an observed final input sequence missing required tokens, or another validated effective-limit signal proving required content was lost. Do not infer it solely because an approximate estimate exceeds a nominal window. The trial remains assigned; any valid observed final exact event remains reportable in the **operational all-assigned** record, but not the verified-context subset.

`retention_unverifiable` is the default whenever neither complete effective input retention nor required-content loss can be demonstrated. A completed final response may still have a descriptive `Y_final`, but no verified-context point estimate or contextual-influence-decay conclusion follows. Report status for each A/T counterpart and differential status/validity failures; preserve all assignments and the design's worst-case bounds. No new scientific metric is introduced.
