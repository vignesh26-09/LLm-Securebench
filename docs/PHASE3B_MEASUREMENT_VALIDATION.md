# Phase 3B measurement validity and eligibility

## Observations, labels, and predictions are different objects

The controlled runner saves actual model text, full ordered request history, source/model digests, configuration, timestamps, provider context evidence, and failure status. This is **observed behavior**, not an attack-success label. `docs/EVALUATOR_RUBRIC.md` v1 defines the five human outcomes (`success`, `failure`, `partial`, `ambiguous`, `unavailable`) against a declared legitimate task and attack objective. The existing blinded export → two independent judgments → separate adjudication → append-only import workflow is test-covered; no real Phase 3B human judgments exist. Its labels must be collected by people, never generated by this code.

The historical Gemma `safety_stance < 0.5` mapping was compared with JailbreakBench human-majority labels on 295 usable source rows. It yielded TN=51, FP=135, FN=1, TP=108, 53.90% agreement, κ=0.2113. That construct is not a validated target-response jailbreak outcome classifier. It cannot be substituted for independent target-model labels. Stored JBB baseline classifier columns are historical predictions, not new local evaluator executions.

## Metric-specific gate

| Output | Required reference/inputs | Current Phase 3B status |
|---|---|---|
| Isolated ASR | Completed isolated responses; exact predeclared attack objective; independent/adjudicated binary human labels; explicit classified denominator and excluded `partial`/`ambiguous`/`unavailable` counts. | **Insufficient data.** Pilot objective is a synthetic formatting task and has zero human labels. |
| BSDA components | Compatible baseline/perturbed response representations for semantic, safety, instruction, and structure distances; versioned component calibration and a validated interpretation. | **Insufficient data.** No validated pilot representations/calibration. The existing four formulas were unchanged. |
| SAEA paired context effect | Measured behavioral states for matched isolated and sequential attack instance, same model/configuration/case; valid context and non-suspect isolation. | **Insufficient data.** No validated states, and Ollama pilot isolation is `isolation_unverifiable`, not verified. Existing undefined/blocked deltas remain null. |
| Recovery capability | Baseline state, attack state, successive probe states, applicability calibration, and matched benign trajectory where the study comparison requires it. | **Insufficient data.** Pilot has actual probe responses but no validated behavioral states or recovery calibration. Existing applicability rules were unchanged. |
| Evaluator validation | Independent held-out human reference with related-group split, fixed task-aligned rubric, coverage and subgroup error intervals, and a claim-specific eligibility policy fixed before seeing test outcomes. | **Not established.** Phase 3A comparison is exploratory on historical rows; no new held-out Phase 3B labels. |

The new matched benign lane addresses a design omission but does not itself validate a metric. It matches turn and probe counts; content/topic/length equivalence must be reviewed case by case. Context-window accounting is evidence about sent histories, not proof that a model attended to every turn. The canary policy is disabled in the pilot, so canary evidence is `canary_not_applicable`; provider cache isolation remains unverifiable. These statuses are preserved rather than promoted to verified.

## Validation sequence before scientific inference

1. Select a legally usable, version-pinned target dataset with exact tasks/objectives/categories and related-group development/validation/test splits. Review near-duplicate flags manually.
2. Freeze an outcome rubric with case-specific success criteria. Conduct independent blinded annotation, adjudicate disagreement, report inter-annotator agreement and coverage, and retain source hashes.
3. Develop a task-aligned automated evaluator only on development data. Fix mappings and claim-specific error limits before held-out testing; report FP/FN, calibration, coverage, subgroup behavior, and grouped intervals. If it fails, retain human outcomes and block automated conclusions.
4. Validate safety/helpfulness and other behavioral representations against independent reference judgments. Version their calibration separately from BSDA/RC/SAEA formulas.
5. Compute paired/grouped estimates only after matched controls, context and isolation evidence, applicability, and missingness gates pass. Resample by case/related goal, not by individual turn; report exclusions and multiplicity decisions.

Synthetic unit tests establish code behavior only. They do not supply research labels, measurement reliability, or an empirical validation sample.
