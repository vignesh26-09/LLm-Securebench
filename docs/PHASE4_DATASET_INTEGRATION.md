# Phase 4 source integration and lineage

**Status (11 October 2026): real, source-pinned data integrated for a two-case exploratory pilot. This is not a held-out production study.** Raw prompts and responses are restricted research data; this document identifies them by index and hash rather than reproducing them.

The source is [JailbreakBench JBB-Behaviors](https://huggingface.co/datasets/JailbreakBench/JBB-Behaviors), revision `886acc352a31533ffbcf4ef22c744658688086fc`, and three [official attack-artifact files](https://github.com/JailbreakBench/artifacts), repository revision `909e68c01d94222b8ad2e397a017e2e12e2adb73`. Both repositories carry MIT license files in the pinned local directories. The behavior `Source` field also names constituent origins; reuse of constituent content and citations needs review before public redistribution. These historical attack strings were made against other target models. They are source attacks, not evidence of efficacy against the two local models.

The offline audit in `scripts/inspect_phase4_jbb.py` checks source hashes, CSV schema, category/index consistency, nonempty artifact prompts, and historical-calibration overlap. Its persisted result is `experiments/phase4/jbb_source_audit.json`: 100 harmful and 100 benign behaviors; 10 harmful categories with 10 goals each; 79 indices have all three aligned artifacts. Nine harmful goals exactly overlap the historical 300-row judge-calibration source, and 13 reach the audit's lexical near-duplicate threshold of 0.9. Lexical screening is only a conservative aid, not semantic deduplication or proof that the models have never seen a goal.

Before local target responses were collected, `scripts/prepare_phase4_jbb_pilot.py` selected source indices **1** and **51**, in different categories, with complete three-method alignment and no exact or lexical-near historical calibration-goal overlap. It rejects a changed source, selection, artifact goal/category, or locked output. The selection was for coverage and source separation, not statistical representativeness. The same-index benign behavior matches category but has **not** been validated as a semantic or length-matched control. Repeated harmful goals used as recovery probes are also not an independently validated recovery task. The exact pilot dataset is `experiments/phase4/jbb_pilot_dataset_v1.json` (SHA-256 `9c815d6d89b35a5ed5729a883e037c2e52e6411d97f7de0a06361844bdcfc1ba`), with per-attack family, upstream file, prior target, and prompt hash. `scripts/build_phase4_dataset_manifest.py` created the separate immutable `experiments/phase4/jbb_research_manifest_v1.json` (SHA-256 `9e851f43f688617ab44495f4fc57a8ba62b20182cac6d4bd0cdcc7631726820c`).

The historical judge calibration data cannot serve as fresh target responses or new human labels. The source selection excludes its detected goal overlaps, but does not establish a held-out validation split against all published/model-training data. For production, group all variants of a source goal and related artifacts in the same split; freeze the split and licenses before response collection; retain immutable checksums and a private response join map. No development/validation/test split is claimed for the current two-case pilot.

The project intentionally ignores `data/external` in Git because it contains third-party attack text. On a fresh checkout, explicitly run `& 'F:\SecureLLM\.venv\Scripts\python.exe' scripts\fetch_phase4_jbb_sources.py` from the project root to retrieve only these seven small pinned files from the official repositories. The fetcher resolves exact upstream revisions, verifies each SHA-256 before writing, never overwrites a modified local file, and downloads no model weights. Set `TEMP` and `TMP` to `F:\SecureLLM.tmp` for that command. Network access is required; the saved manifest and audit are not substitutes for the source files.
